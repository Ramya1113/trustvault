# TrustVault Security Threat Model & Mitigations

This document outlines the primary security threats addressed by TrustVault, the server-side architectural mitigations implemented in the codebase, and the automated tests proving their effectiveness.

Only threats with active mitigations in the current codebase are listed below.

---

## Threat Matrix

| Threat | Attack Vector / Scenario | Mitigation in TrustVault | Enforcing Implementation File | Automated Test Proof |
| :--- | :--- | :--- | :--- | :--- |
| **IDOR** *(Insecure Direct Object Reference)* | An attacker changes the document ID in the URL (e.g. `/documents/42`) to view or download a document belonging to another user in the same tenant. | Centralized server-side check in `can()` verifies user ownership or an active, non-revoked `AccessGrant` for the requested document ID before returning any data. Returns HTTP 403 Forbidden. Never relies on UI button hiding. | [`app/permissions.py`](file:///d:/trustvault/app/permissions.py#L56-L170)<br>[`app/blueprints/documents.py`](file:///d:/trustvault/app/blueprints/documents.py#L50-L75) | `tests/test_integration.py`<br>`test_integration_viewer_cannot_open_unshared_document_by_id`<br><br>`tests/test_permissions.py`<br>`test_full_permission_matrix` |
| **Cross-Tenant Access** *(Multi-Tenancy Data Leakage)* | A user from Organization B probes URLs or API routes to view, download, edit, or grant access to documents belonging to Organization A. | **Rule 4 (checked first):** `if document.org_id != user.org_id: return False`. All database queries strictly scope models by `org_id == current_user.org_id`. Out-of-tenant requests abort with 404/403 and log a denied attempt. | [`app/permissions.py`](file:///d:/trustvault/app/permissions.py#L94-L101)<br>[`app/blueprints/documents.py`](file:///d:/trustvault/app/blueprints/documents.py#L50-L75)<br>[`app/blueprints/sharing.py`](file:///d:/trustvault/app/blueprints/sharing.py#L148-L165) | `tests/test_integration.py`<br>`test_integration_cross_tenant_user_blocked_with_valid_document_id`<br><br>`tests/test_sharing.py`<br>`test_cannot_grant_access_to_cross_tenant_user` |
| **Privilege Escalation** | A viewer attempts to upload documents, access sharing management routes, or invoke admin user management; or an admin attempts to deactivate/demote the sole admin leaving the tenant orphaned. | **Rule 6:** Viewers can never manage access under any circumstances. Upload is restricted strictly to `admin` and `owner`. Admin routes require `manage_users`. Admin safety rules explicitly block deactivating or demoting the last active administrator. | [`app/permissions.py`](file:///d:/trustvault/app/permissions.py#L112-L145)<br>[`app/blueprints/admin.py`](file:///d:/trustvault/app/blueprints/admin.py#L150-L245) | `tests/test_integration.py`<br>`test_integration_viewer_cannot_upload`<br>`test_integration_viewer_cannot_call_grant_endpoint`<br><br>`tests/test_admin.py`<br>`test_admin_cannot_deactivate_last_active_admin`<br>`test_admin_cannot_demote_last_active_admin` |
| **Audit Tampering** | An attacker or insider with database access mutates or deletes audit logs to hide unauthorized activity. | Append-only audit log with Merkle SHA-256 hash chaining (`entry_hash = SHA-256(prev_hash + data)`). SQLAlchemy event listeners block ORM `UPDATE` and `DELETE` queries. `verify_chain(org_id)` recomputes hashes and pinpoints broken rows. | [`app/audit.py`](file:///d:/trustvault/app/audit.py#L21-L202)<br>[`app/models.py`](file:///d:/trustvault/app/models.py#L320-L355) | `tests/test_integration.py`<br>`test_integration_tampered_audit_row_is_detected`<br><br>`tests/test_audit.py`<br>`test_tampered_row_in_db_fails_verify_chain`<br>`test_audit_log_append_only_enforced_by_orm` |
| **Malicious Upload** | An attacker uploads executable scripts (`.exe`, `.sh`, `.php`) or oversize files (> 5 MB) to achieve remote code execution or cause resource exhaustion. | Strict file extension allowlist (`pdf`, `docx`, `xlsx`, `txt`, `png`, `jpg`, `jpeg`). Max file size enforced at 5 MB (`MAX_CONTENT_LENGTH`). Files stored as raw binary BLOBs in the database (never written to web server disk). Downloads served with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`. | [`app/blueprints/documents.py`](file:///d:/trustvault/app/blueprints/documents.py#L38-L48)<br>[`app/blueprints/documents.py`](file:///d:/trustvault/app/blueprints/documents.py#L295-L308)<br>[`config.py`](file:///d:/trustvault/config.py#L40) | `tests/test_integration.py`<br>`test_integration_oversize_and_disallowed_file_types_rejected`<br><br>`tests/test_documents.py`<br>`test_download_security_headers`<br>`test_upload_extension_allowlist` |
| **Brute Force & Account Enumeration** | An attacker repeatedly submits login attempts to guess passwords or determine whether a username exists. | Thread-safe lockout mechanism tracks failed logins per username and blocks authentication for 10 minutes after 5 consecutive failed attempts (HTTP 429). Generic error message ("Invalid username or password") prevents username enumeration. Passwords require $\ge 10$ characters and are securely hashed with Werkzeug (`pbkdf2`/`scrypt`). | [`app/blueprints/auth.py`](file:///d:/trustvault/app/blueprints/auth.py#L26-L89)<br>[`app/models.py`](file:///d:/trustvault/app/models.py#L122-L128) | `tests/test_auth.py`<br>`test_rate_limit_lockout_after_five_failed_logins`<br>`test_login_generic_error_message` |
| **CSRF** *(Cross-Site Request Forgery)* | An external website tricks an authenticated user into triggering state-changing requests (file upload, grant access, user creation). | Flask-WTF CSRF tokens validated on all state-changing `POST` requests. Session and remember cookies configured with `SameSite=Lax` and `HttpOnly=True`. | [`extensions.py`](file:///d:/trustvault/extensions.py#L15)<br>[`config.py`](file:///d:/trustvault/config.py#L44-L49)<br>[`app/forms.py`](file:///d:/trustvault/app/forms.py) | `tests/test_models.py`<br>`test_config_settings_and_security_flags`<br><br>All blueprint form tests verify CSRF protection. |
